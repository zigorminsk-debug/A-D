# 🩺 Дневник АД (Android)

Полноценное Android-приложение для контроля артериального давления:
дневник измерений, будильники-напоминания и памятка пациента.

> ⚠️ Приложение носит справочный характер и не заменяет консультацию врача.

---

## ✨ Возможности

| Раздел | Что умеет |
|---|---|
| **Дневник** | Добавление/редактирование измерений (АД, пульс, заметка), автоматическая цветовая категоризация по гайдлайнам (оптимальное → криз), сводка за 7 дней, экспорт CSV и PDF-отчёта |
| **График** | Динамика систолического/диастолического давления с целевыми линиями 130/80, периоды 7/30/90 дней и всё время, средние за период |
| **Таблетки** | Препараты с дозировкой и временем приёма, будильники-уведомления («Время принять…»), отметки «принял/пропустил», история приёмов, пауза препарата |
| **Виджет** | Последнее измерение на рабочем столе: АД, пульс, категория, время |
| **Справка** | Справочник препаратов: 25 действующих веществ + комбинации; действие, показания, дженерики, противопоказания, побочные; поиск |
| **Напоминания** | Будильники измерений в заданное время (уведомления), срабатывают ежедневно, переживают перезагрузку телефона, точный режим через AlarmManager |
| **Памятка** | Правила измерения, целевые значения, действия при кризе, «красные флаги» для скорой (103/112), образ жизни, советы по таблеткам |
| **Данные** | Резервная копия одним файлом (JSON): сохранение, восстановление, перенос на новый телефон |
| **Обновление** | Само проверяет релиз GitHub `latest-apk` и ставит более новую сборку поверх, с тем же ключом подписи |

Технологии: **Kotlin, AndroidX, Material 3, ViewBinding, AlarmManager**. Измерения хранятся только на телефоне. Интернет нужен лишь чтобы скачать новую версию самого приложения с GitHub.

## 📲 Установка готового APK

1. Скачайте `app-release.apk` (папка `apk/` или артефакт из GitHub Actions).
2. Перенесите на телефон и откройте файл.
3. Разрешите установку из неизвестных источников (настройки → безопасность).
4. При первом запуске разрешите уведомления — это будильники измерений.

Требования: Android 7.0 (API 24) и новее.

## 🚀 Сборка через GitHub Actions

В репозитории A-D workflow лежит в корне: `.github/workflows/android.yml` (срабатывает на каждый push). Если эта папка — отдельный репозиторий, используется `bp-diary-app/.github/workflows/android.yml`. Оба варианта подписывают APK одним и тем же `keystore/bp-diary.keystore`.

1. Создайте репозиторий на GitHub и загрузите содержимое этой папки:
   ```bash
   git init
   git add .
   git commit -m "BP Diary app"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/bp-diary-app.git
   git push -u origin main
   ```
2. Откройте вкладку **Actions** → workflow **Build APK (Дневник АД)** запустится автоматически.
3. Через ~5 минут скачайте артефакт **BPDiary-APK**
   (`BPDiary-release.apk` — его и ставить; `BPDiary-debug.apk` подписан тем же ключом).
   Тот же release-файл публикуется в релиз `latest-apk`.

## 🛠 Локальная сборка

```bash
./gradlew assembleRelease   # APK: app/build/outputs/apk/release/
# или откройте папку в Android Studio и нажмите Run
```

## 🔑 Постоянный ключ подписи (обновления поверх старой версии)

Приложение подписано **постоянным ключом** `keystore/bp-diary.keystore`
(alias `bpdiary`, срок действия 30 лет). Ключ используется и для `debug`, и для
`release` сборок — локально и в GitHub Actions (файл лежит в репозитории).

**Что это даёт:** любую новую сборку (свою локальную или из CI) можно ставить
**поверх** установленной версии — данные измерений сохраняются.

Правила:
1. **При каждом обновлении увеличивайте `versionCode`** в `app/build.gradle`
   (иначе Android не перезапишет APK).
2. Не удаляйте и не пересоздавайте `keystore/bp-diary.keystore` — потеря ключа
   означает, что следующие обновления придётся ставить с удалением данных.
3. Пароли ключа (по умолчанию `BPdiary2026`) можно скрыть в GitHub Secrets:
   задайте переменные `BP_KEYSTORE_PASSWORD`, `BP_KEY_ALIAS`, `BP_KEY_PASSWORD`
   и при желании перенесите сам файл ключа из публичного репозитория в Secrets
   (base64), раскомментировав его восстановление в workflow.
4. ⚠️ **Разово:** если у вас уже стояла версия **1.0** (подпись временная) —
   удалите её один раз, затем установите **1.1**. Все последующие обновления
   будут ставиться поверх без удаления.

| Вариант | Файл |
|---|---|

| B. Тонометр (вектор) | `design/vector-variants/icon_b_meter.xml` |
| C. Капля (вектор) | `design/vector-variants/icon_c_drop.xml` |
| D. Дневник (вектор) | `design/vector-variants/icon_diary_book.xml` |
| **E. Тонометр HD — активная** | `design/icon_e_tonometer.png` → `res/drawable-nodpi/ic_launcher_fg.png` + mipmaps |
| F. Сердце+пульс HD | `design/icon_f_heart_pulse.png` |

**Как включить другой вариант:**
- **E/F (растровые):** замените `app/src/main/res/drawable-nodpi/ic_launcher_fg.png` на нужный PNG (квадрат 512×512) и пересоберите — адаптивная иконка подхватит его сама.
- **A–D (векторные):** скопируйте выбранный XML в `res/drawable/ic_launcher_fg.xml`, удалив PNG-версию, и в `mipmap-anydpi-v26/ic_launcher.xml` оставьте foreground `@drawable/ic_launcher_fg`.

**Фон главного экрана** (уже подключён светлый):
- Светлый: `res/drawable-nodpi/bg_light.png` — активен (`Theme.BPDiary → android:windowBackground`)
- Тёмный: `res/drawable-nodpi/bg_dark.png` — заменить в теме, чтобы включить
- Вернуть однотонный: в теме `@drawable/bg_light` → `@color/bg`
